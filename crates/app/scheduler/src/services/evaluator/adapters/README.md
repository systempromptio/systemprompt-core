# Native evaluator adapters

Adapters construct argv and isolated configuration for the shared container supervisor. The supervisor verifies retained image and executable digests, applies network and resource limits, captures raw evidence, and confirms cleanup. Gateway requests remain the accounting authority: native token fields are advisory and absent values stay unknown.

OpenCode's `opencode-native-v2` contract targets Linux OpenCode **1.18.29**. Its executable is `/usr/local/bin/opencode`; skills reside in the isolated home's `.config/opencode/skills`. Experiment serialization continues using `opencode`, with `open-code` accepted as an alias and used by capability presentation.

`run --format json` uses an explicitly named agent. The pinned `opencode-runner.cjs` supplies per-run `OPENCODE_CONFIG_CONTENT` and purpose-specific permissions. Native `steps` is advisory: the pinned upstream turns it into a maximum-step prompt, which cannot enforce an HTTP request ceiling. The parent runner therefore counts every provider attempt before forwarding, clamps output limits and rejects attempts beyond the admitted maximum. It uses the shared authenticated loopback relay with a distinct OpenCode chat/tool allowlist. A private PID namespace hides the parent process, and mounted native configuration replaces the upstream capability with a fresh local-only credential. The original credential configuration is hidden; installed skills are read-only, and only isolated native state/cache and the purpose-appropriate workspace are writable. The retained private configuration restricts the provider and MCP fixture to the execution relay, disables sharing, updates, compaction and project configuration discovery, and starts with empty native authentication storage. Judges and suggestions deny editing, skills and MCP calls. External-directory permissions deny access to other configuration and credentials. The immutable image and isolated home must contain no unmanaged configuration or plugins; native acceptance checks this before a target can be registered.

JSON events are bounded and deduplicated by immutable part identity within one native session. Independent step usage is summed only when all contributing steps report the field. Conflicting parts, mixed sessions, malformed usage and oversized streams fail normalization. A terminal `stop` step completes a result only when the runner does not report a process, output or attempt-bound failure; errors and unfinished or limit-exhausted steps cannot produce successful judgments. Raw output and gateway-accounted failed spend remain available through the supervisor on normalization failure.

The implementation follows the pinned upstream [run event protocol](https://github.com/anomalyco/opencode/blob/v1.18.29/packages/opencode/src/cli/cmd/run.ts), [configuration loader](https://github.com/anomalyco/opencode/blob/v1.18.29/packages/opencode/src/config/config.ts), [maximum-step prompt](https://github.com/anomalyco/opencode/blob/v1.18.29/packages/core/src/session/runner/max-steps.ts), and [agent schema](https://github.com/anomalyco/opencode/blob/v1.18.29/packages/core/src/v1/config/agent.ts). CLI argument and event fixture tests do not establish native isolation or gateway metering. A target remains unavailable until both retained native proofs exist. An out-of-tree acceptance recipe records bounded offline version, executable, CLI-surface and container-isolation checks; it does not claim gateway metering or enable an evaluator target.

## Codex

`codex-native-v1` targets Linux Codex **0.154.0**, with its native executable and sibling resources copied from the exact npm platform package into `/opt/systemprompt/codex`. The executable hash checks `bin/codex`, rather than the npm JavaScript launcher. Skills are installed under the isolated home's `.agents/skills`.

The pinned image includes `codex-runner.cjs`. It starts an authenticated listener on **127.0.0.1:8091**, forwards only Responses and declared fixture MCP operations to the exact execution relay, and replaces upstream authentication with the execution's retained token and session. Every authenticated provider attempt consumes the configured attempt allowance before forwarding, including malformed requests and failed retries. Requests are bounded to 1 MiB, responses to 16 MiB, forwarding concurrency to four, and upstream inactivity to 30 seconds. The runner checks the admitted model and clamps output-token requests; redirects and ambient proxies are never followed. Gateway accounting remains authoritative.

Codex receives only a random loopback credential and an allowlisted environment. Sandbox profiles deny `/proc` and private Codex configuration, permit read-only installed skills for executions, forbid command networking, and give judges/suggestions read-only workspaces without fixture MCP access. Explicit configuration disables hooks, plugins, apps, web search and delegation. User config and execpolicy rules are ignored; project configuration remains untrusted. Raw JSONL and failed spend survive failed or malformed terminal evidence.

The implementation follows the official [non-interactive execution contract](https://learn.chatgpt.com/docs/non-interactive-mode), [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference), and [permission profiles](https://learn.chatgpt.com/docs/permissions). An out-of-tree runner acceptance recipe tests a deterministic local HTTP fixture; a native acceptance recipe additionally checks the exact native version, pinned files, CLI flags, and sandbox credential/read/write canaries without model inference. Neither recipe alone enables a native target or proves gateway metering.

## Hermes

`hermes-native-v1` implements Hermes **0.21.3**, release `v2026.9.14`, from exact upstream commit `345cd2b057a452236de401d3534b8502a7465e8d`. The four-client image installs its frozen upstream dependency lock and keeps its console executable at `/opt/hermes-source/.venv/bin/hermes`. Installed skills live at the isolated home's `.hermes/skills` and are mounted read-only into the native process.

Hermes oneshot mode bypasses interactive approval, so the adapter does not rely on those prompts for isolation. The pinned runner starts the CLI inside bubblewrap with a separate PID namespace, a read-only root and configuration, private writable state, read-only skills, and workspace writes only for executions. Only file operations and the declared fixture MCP server are selected; terminal, browsing, delegation, memory, inline skill commands, hooks and ambient plugins are excluded. The native process receives a random local credential, never the execution relay credential. Failure to establish the native namespace remains an actionable failed launch.

The shared authenticated loopback relay uses an explicit chat wire for Hermes and keeps the Responses route exclusive to Codex. It checks the exact model and allowed tool schemas, rejects incompatible token fields, clamps both chat output-limit variants, and counts failed retries before forwarding. Tool observations come from native tool results included in subsequent provider requests. Native final text and stderr are wrapped in sequenced JSON events, followed by the usage-file evidence and actual process exit. Missing, linked, oversized, malformed, incomplete or identity-mismatched usage cannot establish successful completion. Native usage is explicitly not independently verified; failed gateway spend remains authoritative even if that file is tampered with.

The implementation follows the pinned upstream [CLI reference](https://github.com/NousResearch/hermes-agent/blob/345cd2b057a452236de401d3534b8502a7465e8d/website/docs/reference/cli-commands.md), [oneshot implementation](https://github.com/NousResearch/hermes-agent/blob/345cd2b057a452236de401d3534b8502a7465e8d/hermes_cli/oneshot.py), and [toolsets](https://github.com/NousResearch/hermes-agent/blob/345cd2b057a452236de401d3534b8502a7465e8d/toolsets.py). Out-of-tree acceptance recipes cover image builds, local runner contracts, and offline native CLI/namespace canaries. All automated targets remain unavailable until actual native isolation and gateway metering proofs have been retained.
