# Native evaluator adapters

Adapters construct argv and isolated configuration for the shared container supervisor. The supervisor verifies retained image and executable digests, applies network and resource limits, captures raw evidence, and confirms cleanup. Gateway requests remain the accounting authority: native token fields are advisory and absent values stay unknown.

OpenCode's `opencode-native-v1` contract targets Linux OpenCode **1.18.29**. Its executable is `/usr/local/bin/opencode`; skills reside in the isolated home's `.config/opencode/skills`. Experiment serialization continues using `opencode`, with `open-code` accepted as an alias and used by capability presentation.

`run --format json` uses an explicitly named agent. A shell-free `/usr/bin/env` invocation supplies per-run `OPENCODE_CONFIG_CONTENT` with requested step/output limits and purpose-specific permissions. The retained private configuration restricts the provider and MCP fixture to the execution relay, disables sharing, updates, compaction and project configuration discovery, and starts with empty native authentication storage. Judges and suggestions deny editing, skills and MCP calls. External-directory permissions deny access to other configuration and credentials. The immutable image and isolated home must contain no unmanaged configuration or plugins; native acceptance checks this before a target can be registered.

JSON events are bounded and deduplicated by immutable part identity within one native session. Independent step usage is summed only when all contributing steps report the field. Conflicting parts, mixed sessions, malformed usage and oversized streams fail normalization. A terminal `stop` step completes a result; errors and unfinished or limit-exhausted steps cannot produce successful judgments. Raw output and gateway-accounted failed spend remain available through the supervisor on normalization failure.

The implementation follows the pinned upstream [run event protocol](https://github.com/anomalyco/opencode/blob/v1.18.29/packages/opencode/src/cli/cmd/run.ts), [configuration loader](https://github.com/anomalyco/opencode/blob/v1.18.29/packages/opencode/src/config/config.ts), and [agent schema](https://github.com/anomalyco/opencode/blob/v1.18.29/packages/core/src/v1/config/agent.ts). CLI argument and event fixture tests do not establish native isolation or gateway metering. A target remains unavailable until both retained native proofs exist. Astound's `just evals-opencode-native` records bounded offline version, executable, CLI-surface and container-isolation checks; it does not claim gateway metering or enable an evaluator target.

## Codex

`codex-native-v1` targets Linux Codex **0.154.0**, with its native executable and sibling resources copied from the exact npm platform package into `/opt/systemprompt/codex`. The executable hash checks `bin/codex`, rather than the npm JavaScript launcher. Skills are installed under the isolated home's `.agents/skills`.

The pinned image includes `codex-runner.cjs`. It starts an authenticated listener on **127.0.0.1:8091**, forwards only Responses and declared fixture MCP operations to the exact execution relay, and replaces upstream authentication with the execution's retained token and session. Every authenticated provider attempt consumes the configured attempt allowance before forwarding, including malformed requests and failed retries. Requests are bounded to 1 MiB, responses to 16 MiB, forwarding concurrency to four, and upstream inactivity to 30 seconds. The runner checks the admitted model and clamps output-token requests; redirects and ambient proxies are never followed. Gateway accounting remains authoritative.

Codex receives only a random loopback credential and an allowlisted environment. Sandbox profiles deny `/proc` and private Codex configuration, permit read-only installed skills for executions, forbid command networking, and give judges/suggestions read-only workspaces without fixture MCP access. Explicit configuration disables hooks, plugins, apps, web search and delegation. User config and execpolicy rules are ignored; project configuration remains untrusted. Raw JSONL and failed spend survive failed or malformed terminal evidence.

The implementation follows the official [non-interactive execution contract](https://learn.chatgpt.com/docs/non-interactive-mode), [configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference), and [permission profiles](https://learn.chatgpt.com/docs/permissions). Astound's `evals-codex-runner` recipe tests a deterministic local HTTP fixture; `evals-codex-native` additionally checks the exact native version, pinned files, CLI flags, and sandbox credential/read/write canaries without model inference. Neither recipe alone enables a native target or proves gateway metering.
